# v1.2.0-rc21: upgrade notes (from rc19)

What a site upgrading from `v1.2.0-rc19` to `v1.2.0-rc21` needs to know. The full list of
what the release is, and its known limits, is in [`v1.2.0.md`](v1.2.0.md) and
[`CHANGELOG.md`](../../CHANGELOG.md). How to upgrade is guide 06 §2
([`06-operations-runbook.md`](../guides/06-operations-runbook.md)).

## Which version to start from

**rc19 is the previous published candidate.** `v1.2.0-rc20` was tagged but never published:
its release run failed, so there is no rc20 release, image or signature. Upgrade from rc19
straight to rc21. A site still on rc18 or earlier upgrades the same way; read the notes of
each candidate it skips in `CHANGELOG.md`.

## Database: no migration

rc19 and rc21 carry the same Alembic revisions (81 files in each; no revision added,
changed or removed). The upgrade is an image bump. The pre-upgrade backup (`tn_pre_upgrade_backup`,
on by default) still runs.

## Settings: nothing new is required

The installer diff between the two tags is two edits, a README paragraph and one longer
error message in `80-seed`. No new variable, no changed default, no new required vault key.

One thing to check if your site sets `tn_platform_tenant_id` (a tenant other than the
bootstrap tenant): the **bootstrap administrator must belong to that tenant**, because only
the platform administrator may now configure the AI backend (below). On a single-tenant
site, nothing to check.

## Behaviour that changed

Security fixes from the #443 audit. Each is a refusal that did not exist before; none moves
data.

- **AI backend:** only the platform administrator can read or change it. Another tenant's
  administrator now gets 403 on `/ai-config` and sees an error on the AI settings page.
- **A range's build output** (`provisioner_output`) is no longer returned to Students and
  Observers.
- **Lab tokens:** a lab token stops working when its owner's account is disabled; "Start
  lab" on a lab that is ending hands back a token the lab page can use.
- **Classes:** a lead instructor can no longer move an approved class's end date later (the
  hold and ranges had been stretching with it).
- **Ranges:** a partial build is not recorded ready, and a partial teardown is not recorded
  destroyed. A snapshot cannot be deleted over a pending credential rotation, and a
  never-applied account is not rotated.
- **cmi5:** the AU's LRS proxy no longer blocks the API's event loop, so one slow LRS call
  cannot stall other requests.

Other changes:

- **Team exercises are judged by the instructor** (ADR 0020, superseding the auto-credit of
  ADR 0005): a detection is evidence the instructor reads and acknowledges; nothing is
  credited automatically. See guide 04.
- **Consoles:** the guides now describe the console as opening on the page and relayed
  through TrueNorth (a documentation change; the relay itself shipped earlier).
- **Dependencies and images:** OpenTelemetry 1.45.2 (CVE-2026-126360) and the Moodle image's
  `musl` upgrade (CVE-2026-107891), so the release scan passes.

## Known limits that still apply

[`v1.2.0.md`](v1.2.0.md) lists them. The #443 audit's other findings (42 held at the
time of writing) are tracked in #443 and #493 and are not fixed here; for example, a
demoted assistant keeping staff rights on a class is not among rc21's fixes. After the
upgrade, the installer's smoke test proves health, readiness and sign-in (guide 06 §2.3);
then read System Health.

## Rollback

rc21 to rc19 needs no schema change either, so an image rollback is safe with respect to the
database (guide 06 §2.4: the installer refuses to go backwards unless told to).
