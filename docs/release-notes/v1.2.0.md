# TrueNorth Range v1.2.0: known limitations, simulator-only evidence and staging record

What changed is in [`CHANGELOG.md`](../../CHANGELOG.md) (v1.2.0). How a release is built,
signed and verified is in [`docs/release.md`](../release.md). This page covers what does not
work yet, what is proven only against simulators, and what was verified on staging.

Written 2026-10-11 against `v1.2.0-rc3` (on staging) and the release-readiness branch
`claude/release-ready-gaps`.

## Known limitations in v1.2.0

### vSphere work is proven on simulators only

There is still no run against a real vCenter. The live lab workflow (`lab.yml`) is manual
only until its self-hosted runner is registered (`docs/runbooks/lab-runner.md`), and
staging has no vCenter (a simulated, read-only one for the dashboards). See
[Simulator-proven only](#simulator-proven-only) for the list.

### ARC² test-host content is unreviewed

On staging the ARC² runner accepts the outline and preview gates by itself
(`ARC2_AUTO_ACCEPT_GATES`, `accepted_by: auto (test host)`, badged "TEST CONTENT"), and the
batch driver accepts each release's open actions. Staging's 45 courses are therefore test
content: never release them to Students or copy them to another host
(`docs/content-library.md`, `docs/arc2-course-studio.md` §13–15).

### C105's release is a fixture, and C105 stays a draft

`content/releases/c105-foundations-d0e83b9f6c1f.tar.gz` is the fixture for the cmi5 API
tests and the CATAPULT lane. The shipped-content load and the ARC² batch no longer publish
C105 (`KEEP_DRAFT`), but a host that published it before keeps it published: unpublish it
by hand.

### cmi5 and LTI

- A cmi5 Moodle activity is tied to one course release.
- An LTI cmi5 launch does not enrol the Student in the TrueNorth course.
- WebSockets do not accept the LTI hand-off session (live updates need a direct
  TrueNorth sign-in).

### Carried over from v1.0.0

- Student telemetry search on range indices created before the v1.0.0 upgrade (workaround
  in `docs/release-notes/v1.0.0.md`).
- Multi-tenant installs must set `PLATFORM_TENANT_ID`.
- LTI needs HTTPS.

Resolved since v1.0.0: staff deep linking (#132) and H6, per-tenant vCenter credentials
(#131, simulator-proven).

### Operations

- The Prometheus alerts for OpenSearch health, Moodle, the ARC² runner and backups (new in
  this branch) are unit-tested with promtool; alert delivery through Alertmanager has not
  been exercised on staging.
- The nightly backup does not stop the ARC² runner: a job running at that moment may be
  captured half-written (recorded in the manifest). Restore needs the runner stopped
  (`docs/runbooks/backup-restore.md`, "ARC² runs").

## Simulator-proven only

Each of these passes in CI against a simulator or fake, and has **not** run against real
infrastructure:

| Feature | Proven against | Lane / tests |
|---|---|---|
| Range provisioning through `vsphere_api` | govmomi vcsim | CI `vsphere-sim` |
| Per-tenant vCenter credentials for every vSphere operation (H6, #131) | vcsim and fakes | CI `vsphere-sim`, worker unit tests |
| VyOS and OPNsense receive the range's rendered config (#131) | vcsim and fakes | worker unit tests |
| Greyspace on vSphere: gs-core VM, `configure_range`, mail/NTP/HTTPS, NPC traffic, breadcrumb inject (#133) | vcsim and the T0 Docker stack | CI `greyspace`, `docs/release-notes/greyspace-vsphere.md` |

Proven against real third-party implementations in CI, not on staging: the cmi5 runtime
(ADL CATAPULT, CI `cmi5`) and Moodle publication (a disposable Moodle, CI `moodle`).
