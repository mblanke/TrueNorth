# Implementation Rules
## Change policy
- Prefer edits over rewrites.
- Keep changes localized.
- One change = one purpose.
## Dependency policy
- Default: do not add dependencies without justification.
- If adding: explain why, alternatives considered, and impact.
## Error handling
- Validate inputs at boundaries.
- Error messages must be actionable.
- Use HTTP status codes correctly (400/401/403/404/409/422/500).
